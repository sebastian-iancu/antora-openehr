// @overview
Framework for certifying openEHR platform implementations. Defines conformance profiles, test cases per REST API endpoint, and a certificate scheme for verifying vendor compliance against the openEHR specifications.

// @spec:guide
Comprehensive guide to the openEHR conformance framework. Covers conformance profiles, test categories, assessment methodology, and the certification process for platform implementations. It explains how conformance profiles are structured, what a test schedule contains, and what evidence is required to obtain a conformance certificate. Platform vendors and procurement teams use this guide to understand what compliant behaviour means and how it is verified.

// @spec:platform_test_schedule
Detailed test schedule specifying test cases for each openEHR REST API endpoint and service interface, used to verify and document platform implementation conformance. Tests are organised by API resource and operation, with explicit pre-conditions, request specifications, expected response codes, and response body assertions. The test schedule is the normative basis for automated conformance testing suites used by the openEHR community.

// @spec:profiles
Definitions of conformance profiles grouping REST API capabilities into coherent subsets. Enables partial conformance claims for implementations supporting specific functionality rather than the full API surface. Profiles are named groupings such as Persistent EHR, Query, or Definitions, allowing vendors to claim conformance at a granularity matching their product scope. A platform may be certified against one or more profiles without having to implement the full openEHR API surface.

// @spec:certificate
Specification of the openEHR conformance certificate scheme. Defines how conformance assessment results are documented, structured, and published for certified platform implementations. Certificates reference the specific profile, test schedule version, and evidence set used in the assessment, providing a reproducible record of the conformance claim. Certified implementations are listed in the openEHR conformance register, giving procurers a verifiable basis for vendor selection.
