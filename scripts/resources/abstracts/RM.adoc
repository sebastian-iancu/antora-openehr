// @overview
Core information model of openEHR: EHR structure, demographic model, data types, data structures, and the EHR Extract model. Archetypes constrain RM instances to express domain content.

// @spec:support
Foundation package of the Reference Model. Defines assumed types, external terminology references, version identifiers, and measurement information shared by all other RM packages.

// @spec:data_types
Complete set of clinical and administrative data types: quantities with units and precision, coded text, plain text, date and time representations, proportions, encapsulated media content, and URIs.

// @spec:data_structures
Generic structural types used throughout the Reference Model: single items, lists, tables, and trees, each parameterised to hold any RM data type instance.

// @spec:common
Cross-cutting Reference Model constructs: the archetyped class hierarchy, entry metadata, feeder audit for legacy data, party references, change control, version containers, and directory structures.

// @spec:ehr
Core model of the openEHR Electronic Health Record. Specifies the top-level EHR structure, Composition as the unit of clinical documentation, and the entry hierarchy covering observations, evaluations, instructions, and actions.

// @spec:demographic
Information model for parties and their relationships: persons, organisations, roles, identity types, contact details, and party relationships. Designed for use alongside or independently of the EHR.

// @spec:ehr_extract
Model for packaging and exchanging structured subsets of an EHR between systems, supporting query-driven extraction, synchronisation-based transfer, and discharge summary scenarios.

// @spec:integration
Structures for incorporating legacy or non-archetyped clinical content into an openEHR EHR. Provides a bridge representation enabling incremental migration of existing data from external systems.

// @spec:entity
A general-purpose model for representing real-world entities such as devices, substances, locations, and organisations that participate in clinical events but are not adequately captured by the person-centric demographic model. Provides typed identity, description, and relationship structures for entities referenced in EHR content.
