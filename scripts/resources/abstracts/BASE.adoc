// @overview
Foundation of the openEHR specification stack. Covers the global Architecture Overview, primitive and structured types, identifiers and object references, and the Resource model for authored translatable documents.

// @spec:architecture_overview
Read-first introduction to the openEHR specification stack. Covers the multi-level modelling paradigm, principal components, relationships between specifications, and the global design philosophy of the platform. It provides the essential conceptual grounding for understanding how the Reference Model, Archetype Model, Service Model, and implementation technology specifications relate to each other. Readers approaching openEHR for the first time should start here before exploring the individual component specifications.

// @spec:foundation_types
Primitive and structured types assumed by all openEHR specifications: Boolean, Integer, Real, String, Date, Time, DateTime, Duration, and generic containers such as List, Set, and Interval. These types are not openEHR-specific inventions but rather a formal specification of the primitive types assumed to exist in any host programming environment. BMM schemas and all other openEHR models reference foundation types as their leaf-level value types.

// @spec:base_types
Core identifier and reference types shared across the openEHR specification stack: object identifiers, version identifiers, terminology codes, and typed object references. Object identifiers support both UUID-based and ISO OID-based schemes, while version identifiers encode three-way version logic for branch-aware versioning. Every versioned EHR object, archetype, and terminology reference in the platform is identified using types defined in this specification.

// @spec:resource
Model for authored, translatable, versioned documents. Provides the common structure for all openEHR artefacts requiring author metadata, language support, and annotation capability. It underpins all openEHR authored artefacts — archetypes, templates, guidelines, and information model documents — providing a uniform structure for governance and translation management. The model supports multiple natural language translations of descriptions, annotations, and terminology bindings within a single artefact.

// @spec:iso_18308_conformance_statement
Formal mapping of the openEHR architecture to ISO TS 18308, demonstrating how each EHR architecture requirement defined in the standard is satisfied by the openEHR platform. It maps each requirement to the specific openEHR component or specification that satisfies it, with commentary on the approach taken. This document is primarily of interest to procurement teams and standards bodies assessing openEHR against formal EHR architecture requirements.
